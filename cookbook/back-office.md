# A back office

A company website needs a place where staff edit the news, the services or
the team page without a developer. This chapter adds one to the
[company website](website.md) with Zana 2.2:

- **Screens generated by `make:crud`:** a list, a form per locale, draft →
  published → archived, delete after confirming, and a signed preview link.
- **Signing in** with a session, attempts limited, and a role per editor.
- **A history** of every change, with a way back.
- **Images** with alt texts in each language.

```
composer require mj-zana/session mj-zana/database mj-zana/cache
composer require --dev mj-zana/maker
```

The generated code is covered by the maker package's
`GeneratedBackOfficeRunsTest`, which generates a back office into an empty
application and uses it end to end with no hand edits: sign in, a
validation error, create in two languages, preview the draft, publish,
delete, and a forged form rejected.

## 1. Generating the screens

```
php bin/console make:module Blog --web
php bin/console make:crud Blog Post --translatable
```

`--translatable` gives the form one fieldset per locale of
`translation.locales`; without it, editors write in the first locale only.
The command writes:

```text
modules/Blog/Domain/PostStatus.php                         draft, published, archived
modules/Blog/Infrastructure/Persistence/Migrations/…_create_posts_table.php
modules/Blog/Infrastructure/PostRepository.php             plain SQL, one row per locale
modules/Blog/Presentation/Web/Admin/PostAdminController.php
modules/Blog/Presentation/Web/Admin/PostPreview.php        the signed preview link
modules/Blog/Resources/views/admin/layout.php              only if the module has none
modules/Blog/Resources/views/admin/posts/index.php
modules/Blog/Resources/views/admin/posts/form.php
modules/Blog/Resources/views/admin/posts/confirm-delete.php
modules/Blog/Resources/views/admin/posts/preview.php
```

and registers the repository, the controllers and the routes in
`BlogModule` (or prints the lines to add when the module class has no
`zana:maker` markers). The routes:

| Method | Path | |
|---|---|---|
| GET | `/admin/posts` | the list |
| GET, POST | `/admin/posts/new`, `/admin/posts` | create |
| GET, POST | `/admin/posts/{id}/edit`, `/admin/posts/{id}` | edit |
| POST | `/admin/posts/{id}/publish`, `/admin/posts/{id}/archive` | change the status |
| GET, POST | `/admin/posts/{id}/delete` | confirm, then delete |
| GET | `/preview/posts/{token}` | the draft, for anyone with the link, for an hour |

The admin routes run `SessionMiddleware`, `SessionAuthenticationMiddleware`,
`AuthorizationMiddleware` and `CsrfMiddleware`, and the controller requires
the `posts.edit` permission. Previews answer with `X-Robots-Tag: noindex`.

Run the migration:

```
php bin/console migrate
```

The tables are `posts` (id, status, dates) and `post_translations` (title,
slug, body per locale; a slug is unique within its locale).

## 2. Editors and signing in

Configure the roles and the login page:

```php
// config/security.php
return [
    'secret' => $_ENV['APP_SECRET'],
    'roles' => ['editor' => ['posts.edit']],
    'login' => ['path' => '/login', 'max_attempts' => 5, 'window' => 900],
];
```

Editors come from a `PasswordUserProviderInterface`: `findByLogin()` and
`passwordHashFor()`, usually over an `editors` table. Implement
`PasswordUpgraderInterface` as well and hashes made with old settings are
upgraded at the next login. Alias it in a module:

```php
$services->singleton(Editors::class)
    ->alias(PasswordUserProviderInterface::class, Editors::class)
    ->alias(UserProviderInterface::class, Editors::class);
```

The login controller:

```php
#[Route('/login', methods: ['GET', 'POST'], name: 'login', middleware: [SessionMiddleware::class, RateLimitMiddleware::class, CsrfMiddleware::class])]
#[RateLimit(max: 20, per: 60)]   // per address, on top of the per-login limit
public function login(ServerRequestInterface $request, SessionLogin $login, RequestContext $context): View|ResponseInterface
{
    if ($request->getMethod() === 'GET') {
        return View::make('@Site/login', ['error' => null]);
    }
    $input = FormInput::from($request);
    if ($login->attempt($input->string('email'), $input->string('password'), $context->clientIp()) === null) {
        return View::make('@Site/login', ['error' => 'Wrong email or password.'])->withStatus(422);
    }
    $to = $request->getQueryParams()['to'] ?? '/admin/posts';

    return $this->responses->redirect(is_string($to) && str_starts_with($to, '/') && !str_starts_with($to, '//') ? $to : '/admin/posts', 303);
}
```

- An anonymous visitor to `/admin/…` is sent to `/login?to=/admin/…`.
- A wrong password never says whether the account exists, and the
  session gets a new id at login.
- After `max_attempts` failures for one login or one address within
  `window` seconds, `attempt()` throws `TooManyRequestsHttpException`
  (429 with `Retry-After`).
- Check that `to` is a local path, as above, so the login page cannot
  send editors to another site.

`$login->logout()` signs out (in a POST route, with CSRF). For a "forgot
password" page, `PasswordResetTokens` issues a signed, single-use token
to email, and `consume($token)` returns the user once.

Behind a load balancer or a CDN, configure `http.trusted_proxies` so that
`clientIp()` and secure cookies see the visitor, not the proxy (see
[HTTP](../guides/http.md#behind-a-proxy)).

## 3. Showing the content

The generated code is the back office; the public pages are yours. Query
published posts in the visitor's locale, and answer 404 for a draft or a
missing translation:

```php
#[Route('/blog/{slug}', name: 'blog.show')]
public function show(string $slug, LocaleContext $locale): View
{
    $post = $this->db->table('posts')
        ->select('post_translations.title', 'post_translations.body')
        ->join('post_translations', 'post_translations.post_id', '=', 'posts.id')
        ->where('posts.status', 'published')
        ->where('post_translations.locale', $locale->get())
        ->where('post_translations.slug', $slug)
        ->first() ?? throw new NotFoundHttpException();
    $this->meta->title($post['title'])->description(mb_substr(strip_tags($post['body']), 0, 160));

    return View::make('@Blog/show', ['post' => $post]);
}
```

Render the body with the `markdown` helper from `mj-zana/view-markdown`
when editors write Markdown; raw HTML in it is escaped. The recipes add a
[sitemap and a feed](recipes.md).

## 4. Keeping a history

Inject `Revisions` (from `mj-zana/audit`, see [Audit](../guides/audit.md))
in the generated controller and record each locale after saving:

```php
$id = $this->records->save($id, $translations);
foreach ($translations as $locale => $fields) {
    $this->revisions->record('post', $id, $locale, $fields);
}
```

Unchanged locales record nothing, and the author is the signed-in editor.
Show `$this->revisions->history('post', $id, $locale)` beside the form,
and add a POST route that calls `restore()` and saves what it returns.

## 5. Images

Add an `image_id` column, a file input to the form
(`enctype="multipart/form-data"`), and store the upload with `MediaLibrary`
(see [Media](../guides/media.md)):

```php
$file = $request->getUploadedFiles()['image'] ?? null;
if ($file instanceof UploadedFileInterface && $file->getError() === UPLOAD_ERR_OK) {
    $media = $this->media->store($file, ['en' => $input->string('alt_en'), 'fr' => $input->string('alt_fr')]);
    // save $media->id as image_id
}
```

On the public page, pass `$this->media->find($post['image_id'])` to the
template as `image` and render it with `<?= $this->picture($image) ?>`.

## 6. Making it yours

The generated files are a starting point, not a dependency: edit them
freely, and nothing regenerates them. Common changes:

- **More fields:** add the column to the migration (or a new migration),
  the repository's `save()` and `find()`, `read()` in the controller, and
  the form.
- **Scheduled publishing:** add `publish_at`, and a task that publishes due
  posts every minute (see [Scheduler](../guides/scheduler.md)).
- **Clearing the page cache** after a save when public pages are cached:
  `$pageCache->invalidate('posts')` (see
  [HTTP](../guides/http.md#new-in-22-content-sites)).
- **A second content type:** run `make:crud` again; the screens share the
  admin layout.
